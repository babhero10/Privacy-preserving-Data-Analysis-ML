    Cheat sheet: the two theorems

    Setting. Secret column d ∈ {0,1}ⁿ. A query is any subset S ⊆ {1..n} (one record, everyone, or anything between). The answer is

    a(S) = Σi∈S dᵢ + e(S), with |e(S)| ≤ E

    Theorem 1 (exponential attack, E = αn). Ask all 2ⁿ subsets. Output any c ∈ {0,1}ⁿ with |Σi∈S cᵢ − a(S)| ≤ E for every S. Then c differs from d in at most 4E = 4αn positions.

    Proof. d is consistent, so a consistent c exists. Let A = {i : cᵢ=1, dᵢ=0} and B = {i : cᵢ=0, dᵢ=1}. On S = A, the count of d is 0 and the count of c is |A|, and both are within E of a(A). So |A| ≤ 2E. The same argument on S = B gives |B| ≤ 2E. Hamming(c, d) = |A| + |B| ≤ 4E. ∎ Cost: 2ⁿ queries and about 2ⁿ·2ⁿ checks.

    Theorem 2 (polynomial attack, Dinur–Nissim). If E = o(√n), then about n·polylog(n) random queries let a polynomial-time attacker recover all but o(n) of the bits.

    1. pick m random subsets S₁…Sm (each i joins with probability ½)
    2. find c ∈ [0,1]ⁿ with |Σi∈S_j cᵢ − a(S_j)| ≤ E for all j (a linear program)
    3. round: cᵢ ≥ ½ → 1, otherwise 0

    Why. A candidate that differs from d in k positions changes a random subset's sum by about ±√k/2. If that exceeds 2E, the same two-sided argument as in Theorem 1 shows the batch rules the candidate out. So only candidates with k ≲ E² wrong bits survive: few if E² ≪ n. The page demo uses least squares instead of the LP; exact constants and log factors are in the paper, so check them against your lecture notes.

    What the attack needs

    Only the noisy answers. Not names, not ZIP codes, not any identifier. Hiding or coarsening identifiers (as k-anonymity does) does nothing against it.

    The rule of thumb

    • Noise of size αn: any survivor is at most 4αn bits wrong.
    • Noise well below √n: a fast attack with about n queries recovers almost everything.
    • Noise about √n or larger: both attacks stop working.

    Why random noise isn't the full story

    Independent noise averages out when you ask thousands of questions. A safe design must either cap how many questions get answered, or add enough noise that the total stays safe. That trade-off is what differential privacy formalises with its privacy budget ε.
